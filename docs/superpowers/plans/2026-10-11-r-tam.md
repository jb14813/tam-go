# R-TAM Implementation Plan

This retained plan records the initial local implementation. Steps use checkbox
(`- [ ]`) syntax for tracking. Later network validation and the review branch
handoff are recorded in [the network report](../../R-TAM-NETWORK.md).

**Goal:** Deliver local Rust server and client binaries with the current Go behavior and interoperability, data-safe persistence, and fully validated warning-free builds.

**Architecture:** A Cargo workspace under `rust/` contains shared protocol/persistence code and separate server/client crates. Retain the existing Svelte interface and pinned Go source as the interoperability reference. Durable Rust intents and consistent backups strengthen safety without changing the public Go protocol.

**Tech Stack:** Rust stable 1.98 on Windows; Tokio, Axum, rusqlite/bundled SQLite, serde/serde_json, reqwest/rustls, rcgen, bcrypt, SHA-256, mDNS and platform-specific Windows lifecycle APIs. Check official dependency APIs and commit Cargo.lock. Official references: [Axum](https://docs.rs/axum/latest/axum/), [rusqlite](https://docs.rs/rusqlite/latest/rusqlite/), [reqwest](https://docs.rs/reqwest/latest/reqwest/), [rustls](https://docs.rs/rustls/latest/rustls/).

**Spec:** `docs/superpowers/specs/2026-10-11-r-tam-design.md`.

## Global Constraints

- The reference is Go commit `b530cdad8da7be968e8f640a8de8badc1d113be7`.
- Name the product R-TAM and binaries `r-tam-server` and `r-tam-client`.
- The initial implementation scope was local validation without publication or deployment.
- Avoid temporary migration code for a one-time topology change.
- Reuse the static SvelteKit frontend and server admin visual layout.
- Do not rewrite the UI, replace forms, or introduce new settings.
- Protocol identities remain exactly `TAM Server` and `TAM Client`.
- Preserve `TAM-*` and `X-TAM-*` header names and Go JSON field names.
- Use the exact current Go table/column names, primary keys and report views.
- Keep unknown pre-existing tables intact.
- Do not hide warnings with blanket lint allowances or exclude failing targets.
- Keep test databases, settings, certificates and keys separate from event data.
- Do not claim runtime parity from a build alone.

## Review Focus

- A crash after server acceptance and before acknowledgment must leave a replayable intent that cannot undo a later save.
- A Go-authored repeated save containing escaped Unicode or repeated query values must produce the same digest after Rust takes over its database.
- A deliberate restore may revive a prefix; a stale newer-only merge must not. Pending saves must not undo a restore.
- A failed archive write during pairing/event change must leave data, event and pending queue intact.
- A delayed replay answer or mirror download must not overwrite a newer local edit, and a definitive online rejection must not be replayed as an accepted offline save.

## Ownership and execution order

Use fresh workers with narrow ownership and task review before accepting each deliverable. Tasks 1 and 2 establish the shared interfaces. Tasks 3 and 4 can then run concurrently because their product files are disjoint. Task 5 integrates the completed core, transport and server contracts. Task 6 validates the complete system and produces local deliverables. A controller owns top-level manifests/build commands, the progress ledger, compatibility probes and final integration; workers request manifest changes through the controller rather than editing a shared manifest concurrently.

All workers must be told they are not alone in the codebase and must preserve other workers' changes. Each task uses tests that fail for the missing behavior before product implementation, then passes its affected tests and the available Rust workspace tests. Never substitute a Go wrapper for either Rust backend.

- [x] **Step 1: Write model and wire behavior tests.** Pin integer/null behavior, Go field order/escaping, omitted zero revisions, duplicate row preservation and query ordering. A required-ID test is:

```rust
#[test]
fn required_ticket_id_rejects_null_and_fraction() {
    for input in [
        r#"{"prefix":"A","t_id":null}"#,
        r#"{"prefix":"A","t_id":4.0}"#,
        r#"{"prefix":"A","t_id":"4"}"#,
    ] {
        assert!(wire::decode::<Ticket>(input.as_bytes()).is_err());
    }
    assert_eq!(wire::decode::<Ticket>(br#"{"prefix":"A","t_id":0}"#).unwrap().t_id, 0);
}
```

- [x] **Step 2: Run tests and retain the expected missing-behavior failure.** Use `cargo test --manifest-path rust/Cargo.toml -p r-tam-core --test models` once the minimal test crate exists. Configuration-only scaffolding may precede the first behavior test.
- [x] **Step 3: Implement typed decoding/encoding from `internal/store/models.go` and `edits.go`, including strict integral deserializers and Go defaulting.** For Go HTML escaping, postprocess serialized UTF-8 without changing ordinary strings or field order:

```rust
for byte in serde_json::to_vec(value)? {
    match byte {
        b'<' => out.extend_from_slice(br"\u003c"),
        b'>' => out.extend_from_slice(br"\u003e"),
        b'&' => out.extend_from_slice(br"\u0026"),
        other => out.push(other),
    }
}
```

Also escape U+2028/U+2029, preserve typed struct order and normalize before digesting. Sort decoded query keys while retaining the order of values for each key; use Go's application/x-www-form-urlencoded escaping. Hash `method + " " + path + "?" + query + "\n" + go_json_body`.
- [x] **Step 4: Write and fail schema tests on freshly created and copied Go-layout databases.** Check all tables/columns/views, unknown table preservation and `PRAGMA integrity_check`.
- [x] **Step 5: Implement exact schema initialization from `internal/db/*.go`.** Use permanent `CREATE TABLE IF NOT EXISTS`, inspect columns before required `ALTER TABLE`, rebuild report views transactionally, set 5000ms busy timeout, WAL and FULL synchronous. - [x] **Step 6: Run all core tests, formatting and Clippy; review and commit the protocol/schema deliverable.** Command: `cargo clippy --manifest-path rust/Cargo.toml -p r-tam-core --all-targets -- -D warnings`.

### Task 2: Store edits, reports, revisions, backups and durable queues

**Files:**
- Create: `rust/crates/core/src/store/{mod,rows,edits,order,event,queue,reports}.rs`.
- Create: `rust/crates/core/tests/{store_edits,store_order,store_queue,store_backup,reports}.rs`.
- Modify: `rust/crates/core/src/lib.rs` only to export the store module.

**Interfaces:**
- Consumes Task 1 typed models, validation, schema and Go-compatible encoder.
- Produces a cloneable `Store` owning a database path and serialized write access, with read connections for snapshot exports/reports.
- Produces `Store::open(path: &Path, role: Role) -> Result<Store>`; `Store::export() -> Result<BackupFile>`; `Store::import(&BackupFile) -> Result<()>`; `Store::merge_newer(&BackupFile) -> Result<MergeResult>`.
- Produces typed row list/read and prefix-delete methods, form-save methods returning actual stored rows, and report/search methods matching Go SQL semantics.
- Produces `Store::next_save(host: &str, after: Option<i64>) -> Result<Order>` and transactional ordered server application with `Outcome::{Applied,Repeat,Behind}` plus last number.
- Produces queue APIs to journal an online intent, accept an offline edit atomically, list FIFO pending/failed items, reconcile validated server answers, advance counters, retry/discard failures and quarantine on event change. `QueueItem` carries all existing Go outbox fields.
- Produces snapshot-safe event transition APIs that perform all SQL mutations in one transaction after the caller has flushed an exclusive archive.

- [x] **Step 1: Write and fail tests matching `store/{saves,order,merge,outbox}_test.go`.** The central field test writes a ticket, changes its phone from another client, then submits a stale first-name/phone edit with base values. Assert the safe name edit is accepted, newer phone remains, and returned row has both results.

```rust
assert_eq!(stored.first_name, "Corrected");
assert_eq!(stored.phone_number, "222");
assert!(stored.rev > original.rev);
assert_eq!(store.export()?.tickets, vec![stored]);
```

- [x] **Step 2: Implement per-form field merge and revision stamping.** Use the Go-owned fields only. Each changed field requires `mine != base && current == base`; new rows insert whole; no-base replaces form fields. Ticket/basket/drawing/prefix writes and revision counters commit together under an IMMEDIATE transaction.
- [x] **Step 3: Write and fail duplicate/behind/replay tests, then implement `client_saves` comparison.** Store the save number/hash and row updates in one transaction. Return repeats without mutation and behind saves with the last accepted number. Reject overflow instead of wrapping save/revision counters.
- [x] **Step 4: Write and fail snapshot backup/restore/merge tests.** Ordinary restore upserts supplied rows, retains absent rows, may replace event and clear supplied prefix tombstones. Newer-only merge independently compares basket components and rejects wrong events on a populated server. Add concurrent export consistency and invalid-backup rollback tests.
- [x] **Step 5: Implement backup and report SQL using the pinned Go schema.** Export event plus every table within one read transaction. Search uses literal substrings rather than SQL wildcard injection. Reports preserve ordering, null-to-empty strings, ticket-zero undrawn behavior and distinct `Total` prefix versus aggregate row.
- [x] **Step 6: Write and fail queue rollback, failed retry order, restored counter, newer-local-edit and event-transition tests.** Inject a real SQL-trigger failure during queue insert and assert both row and queue remain unchanged. Journal online intent before network; definitive rejection removes unaccepted intent without local mutation. Offline row+intent commit together. Never acknowledge malformed/incorrectly ordered answer rows.
- [x] **Step 7: Implement queue reconciliation from `outbox.go`, `edits.go: ResultOf/CopyResult/Kept` and `sync.go`.** Preserve a newer local row when an old answer arrives; failed field edits use refreshed base values. Add ancillary permanent Rust intent metadata only if needed; keep pending bodies/identities Go-readable. Finish with workspace tests, Clippy and task review before commit.
